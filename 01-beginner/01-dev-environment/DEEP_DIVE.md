# Chapter 1 Deep Dive: Dev Environment

## Which ROS2 version

This curriculum targets **ROS2 Jazzy Jalisco**, the current Long-Term
Support (LTS) release, which targets **Ubuntu 24.04 (Noble)**. LTS
releases get updates for 5 years, which matters because ROS2 distros are
tied tightly to an Ubuntu version — you can't easily "upgrade" ROS2
without eventually upgrading Ubuntu. If you're on Ubuntu 22.04, use ROS2
Humble Hawksbill instead (also LTS); the commands below are identical
except the distro name.

If you don't have Ubuntu at all: Isaac Sim and Isaac ROS (Tiers 2-4)
require Linux with an NVIDIA GPU, so a dual-boot or bare-metal Ubuntu
install is worth doing now rather than fighting a VM later. WSL2 can run
ROS2 itself, but GPU passthrough for Isaac Sim is unreliable — treat this
curriculum as a native-Linux track.

## Installing ROS2 (apt method)

```bash
# Enable the Ubuntu Universe repository (ROS2 depends on packages in it)
sudo apt install software-properties-common
sudo add-apt-repository universe

# Add the ROS2 apt repository's GPG key and source list
sudo apt update && sudo apt install curl -y
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

# Install the full desktop version (includes RViz2, demos, tutorials)
sudo apt update
sudo apt install ros-jazzy-desktop -y

# Tooling you'll need throughout the curriculum: colcon (the ROS2 build
# tool), rosdep (dependency installer), and common colcon extensions
sudo apt install python3-colcon-common-extensions python3-rosdep -y
sudo rosdep init
rosdep update
```

Why each piece:
- **Universe repo**: many ROS2 dependencies are community-maintained
  packages that live there, not in Ubuntu's default `main` repo.
- **GPG key + source list**: apt only installs from repos it can verify
  are authentic; this tells apt "trust packages signed by this key from
  this URL."
- **`ros-jazzy-desktop`**: there are smaller install profiles (`ros-base`
  has no GUI tools), but `desktop` includes RViz2 and demo packages you'll
  use starting Chapter 2 — worth the extra disk space to avoid gaps later.
- **colcon**: ROS2's build tool. It's what turns your workspace's source
  packages into buildable, runnable code (successor to ROS1's `catkin`).
- **rosdep**: reads a package's declared dependencies and installs them
  via apt/pip automatically — you'll use `rosdep install` constantly once
  you're building packages with dependencies (starting Tier 2).

## Sourcing the environment

Installing ROS2 doesn't put its commands on your `PATH` automatically —
you have to **source** a setup script that sets environment variables
(`PATH`, `PYTHONPATH`, `AMENT_PREFIX_PATH`, and others) every time you open
a new terminal:

```bash
source /opt/ros/jazzy/setup.bash
```

Add it to `~/.bashrc` so it happens automatically in every new terminal:

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
```

**Why this matters and where it bites people:** if you forget to source
(or open a terminal that doesn't have it in `.bashrc` yet, e.g. before
you've added the line), `ros2` commands simply won't exist —
`command not found`. This is the single most common "ROS2 is broken"
report from beginners, and it's almost always just an unsourced terminal.

## Creating a workspace

A **workspace** is a directory where you keep your own ROS2 packages
(as opposed to the system-installed ones under `/opt/ros/jazzy`). Convention
is a `src/` subfolder holding your packages, with `build/`, `install/`,
and `log/` generated by colcon:

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws
colcon build          # builds (currently empty) — creates install/, build/, log/
source install/setup.bash   # adds YOUR workspace's packages to the environment
```

You'll source `~/ros2_ws/install/setup.bash` *in addition to*
`/opt/ros/jazzy/setup.bash` in every terminal where you want to use your
own packages — the system setup script must be sourced first, since your
workspace's setup script builds on top of it (this is called "overlaying").
Chapters 2-3's Python demos don't need a colcon package (they run directly
with `python3`), but the C++ demos and everything from Tier 2 onward do.

## Common pitfalls

- **Locale errors** (`bad locale` or UTF-8 warnings on `ros2` commands):
  run `sudo apt install locales && sudo locale-gen en_US en_US.UTF-8` and
  ensure `LANG=en_US.UTF-8` is set.
- **Missing `python3-colcon-common-extensions`**: without it, `colcon
  build` works but you lose useful extensions like colored output and
  `--symlink-install` support — install it even though colcon works
  without it, so later chapters' build instructions match what you see.
- **`ROS_DOMAIN_ID` collisions**: ROS2 nodes discover each other over the
  network by default (via DDS, covered fully in Chapter 10). If you're on
  a shared network (university lab, coworking space) and someone else is
  also running ROS2, your nodes may see *their* nodes and vice versa,
  causing confusing behavior. Set a unique `ROS_DOMAIN_ID` (0-101) in your
  `.bashrc`: `export ROS_DOMAIN_ID=42` (pick any number, just be
  consistent across your own terminals).
- **Forgetting to re-source after `colcon build`**: colcon build doesn't
  automatically update your current shell's environment — you must
  `source install/setup.bash` again (or open a new terminal) after every
  build for the shell to see newly built/changed packages.
